---
title: Send Message
description: Send plain text to a customer on WhatsApp, Instagram, Telegram or the website widget as an operator via the Pleep API
---

Send a plain text message to a customer from your own systems: on WhatsApp, Instagram, Telegram or the website widget. The message goes out as an operator message, just like a manager's reply from the monitor: it appears in the conversation and in the monitor, reaches your connected CRM, and the AI agent pauses in that conversation.

## Endpoint

```
POST https://microservice.pleep.app/api/v1/messages/send-message
```

## Headers

| Header | Value | Required |
|--------|-------|----------|
| `X-API-Key` | Your API key | Yes |
| `Content-Type` | `application/json` | Yes |

## Who to write to

There are two ways to name the conversation:

- **`thread_id`** works on every channel. It is the same conversation id used by [Lead Stages](/en/api/leads), the [`lead.status_changed`](/en/api/webhooks-outgoing) webhook, [Get Conversation Threads](/en/api/get-threads) and the conversation link in the monitor.
- **`bot_id`, `channel` and `phone`** work for the WhatsApp Business API only: a phone number identifies a customer only on WhatsApp.

The message goes into an existing conversation. On WhatsApp, a new conversation can only be started with a template through [Send Template Message](/en/api/send-template).

## When you can write

| Channel | When plain text can be sent |
|---------|-----------------------------|
| WhatsApp Business API (`waba_coexistence`, `waba`) | Within 24 hours of the customer's last message. After that, only a template through [Send Template Message](/en/api/send-template) |
| Instagram | Within 24 hours of the customer's last message. Instagram has no templates: wait for the customer to write again |
| Personal Telegram account connected officially, through Telegram settings | Within 24 hours of the customer's last message |
| Telegram bot, personal Telegram account with phone number login, WhatsApp through Green API or Wazzup, website widget | Any time |

If the window is closed, nothing is sent and the API answers `422 WINDOW_CLOSED` right away. Phone conversations of a voice agent do not take text: they answer `422 CHANNEL_NOT_SUPPORTED`.

## Request body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `thread_id` | string | Yes, unless `phone` is given | Conversation id on any channel, e.g. `thread_0765c2bd-980d-4c65-aeea-d04069646be5` |
| `bot_id` | string | Yes, unless `thread_id` is given | Bot ID of the WhatsApp number. Step 3 of [Send Template Message](/en/api/send-template) shows where to find it |
| `channel` | string | Yes, unless `thread_id` is given | `waba_coexistence` or `waba` |
| `phone` | string | Yes, unless `thread_id` is given | Customer's number in international format, e.g. `+77001234567`. A plus, spaces and dashes are fine |
| `text` | string | Yes | Message text, up to 4096 characters. On Instagram up to 1000 bytes, about 500 Cyrillic letters |

Pass one of `thread_id` or `phone`. If both arrive, the API answers `422`.

## Examples

### By conversation id, any channel

```bash
curl -X POST https://microservice.pleep.app/api/v1/messages/send-message \
  -H "Content-Type: application/json" \
  -H "X-API-Key: pk_live_your_key" \
  -d '{
    "thread_id": "thread_0765c2bd-980d-4c65-aeea-d04069646be5",
    "text": "Hi! Your order is ready for pickup."
  }'
```

### By phone number, WhatsApp

```bash
curl -X POST https://microservice.pleep.app/api/v1/messages/send-message \
  -H "Content-Type: application/json" \
  -H "X-API-Key: pk_live_your_key" \
  -d '{
    "bot_id": "your-bot-id",
    "channel": "waba_coexistence",
    "phone": "+77001234567",
    "text": "Hi! A reminder about our meeting tomorrow at 11:00."
  }'
```

## Response

```json
{
  "ok": true,
  "data": {
    "thread_id": "thread_0765c2bd-980d-4c65-aeea-d04069646be5"
  }
}
```

`thread_id` is the conversation the message went to. [Get Conversation Threads](/en/api/get-threads) returns the same identifier, and [set-ai](/en/api/leads) takes it.

`ok: true` means the message was accepted and queued for sending, not that the customer has already received it.

## The AI agent after your message

A message sent through the API counts as an operator reply. If "Pause AI when you reply yourself" is on in the [Auto-switch](/en/configuration/operator-settings) extension (it is on by default), the agent pauses in that conversation and stops answering the customer.

To bring the agent back, call [set-ai](/en/api/leads) with `ai_enabled: true` or use the switch in the monitor. If "Turn AI back on when you're done" is also on in Auto-switch, the agent comes back by itself after the time set there.

## Error codes

| HTTP Status | Error Code | Description |
|-------------|------------|-------------|
| 401 | `UNAUTHORIZED` | Missing or invalid API key |
| 404 | `BOT_NOT_FOUND` | No bot with this `bot_id` in the account that owns the API key. Check `bot_id`, `channel`, and that the key was created in the account that owns the number (see [API Keys](/en/api/api-keys)) |
| 404 | `THREAD_NOT_FOUND` | No conversation with this `thread_id` in the key's account, or the customer with this phone has never written to this WhatsApp number |
| 409 | `CHANNEL_NOT_CONNECTED` | The channel of this conversation is no longer connected |
| 422 | `VALIDATION_ERROR` | Missing `text`, no conversation named, both `thread_id` and `phone` given, wrong `channel`, a phone that is not a number, text longer than 4096 characters, or longer than 1000 bytes on Instagram |
| 422 | `WINDOW_CLOSED` | On a channel with a 24-hour window, the customer last wrote more than 24 hours ago or has never written. On WhatsApp, send a template |
| 422 | `CHANNEL_NOT_SUPPORTED` | A phone conversation of a voice agent: there is no chat to write text to |
| 429 | `RATE_LIMITED` | Too many requests. The limit is 120 requests per minute per API key |
